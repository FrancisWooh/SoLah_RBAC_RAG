Aspire Internal Brain —— 平台功能清单 (Feature List)
=====================================================
RBAC 感知的企业内部知识问答平台：员工用自然语言提问，系统只用其有权访问的文档作答，
附来源引用，并把所有查询、拒绝、权限变更写入带哈希链的审计日志。

标记说明： [已实现] 已实现并验证    [部分] 已实现但有限制    [未实现] 范围外/仅架构说明


一、问答（前台 /app/query）
-----------------------------------------------------
1.  [已实现] 文字问答：自然语言提问，基于检索到的文档生成回答。
2.  [已实现] 图片问答：上传图片 → OCR 识别文字 → 走同一条权限流水线（并显示识别结果）。
3.  [已实现] 流式输出：SSE（meta / delta / done），先给判定与来源，再逐段输出回答。
4.  [已实现] 来源引用：回答下方显示来源文档的真实文件名（如 Leave_Policy_Admin_Guide.docx）。
5.  [已实现] 多轮对话：会话历史保存，可继续追问；侧栏按时间分组，支持打开、删除会话。
6.  [已实现] 中英文混合检索（跨语言相似度分数偏低，见限制）。
7.  [已实现] 无权限时明确提示“无权限访问该内容”，不泄露文档是否存在、标题或 ID。
8.  [已实现] LLM 失败自动降级：返回检索到的原文摘录并注明，不报错。
9.  [未实现] 语音查询（/api/query/audio）。


二、权限模型（RBAC + 密级 + 需知分区）
-----------------------------------------------------
10. [已实现] 三重校验：allowed_roles ∩ 用户角色 ≠ ∅，required_clearance ≤ 用户密级，
            compartments ⊆ 用户分区。
11. [已实现] 检索前置过滤（向量库预过滤）+ 应用层最终校验（rbac_filter，所有后端共用，不可绕过）。
            被拒内容不进入模型上下文，不存在“诱导模型说出”的路径。
12. [已实现] 有效角色 = 永久角色 + 未过期的临时/项目角色；授予、撤销立即生效
            （Redis 缓存 30s TTL，带主动失效）。
13. [已实现] 14 个模拟 SSO 账号（无密码，仅演示）：alice、carol、dave、erin、frank、gina、
            henry、ivy、jack、bob、kate、leo、vera、admin；所有人隐含 employee 角色。
14. [已实现] admin（platform_admin）只管理权限，不能读业务内容。
15. [已实现] 只读身份 auditor：仅能访问 MCP 审计接口，不能调用 REST 管理接口。
16. [已实现] 提示词注入防护：检索内容以 <document> 标签作为“不可信数据”交给模型；
            授权从不依赖模型。


三、临时角色与项目角色
-----------------------------------------------------
17. [已实现] 管理员直接授予/撤销角色（可设到期时间）。
18. [已实现] 项目成员：加入项目自动授予项目角色，移出自动撤销。
19. [已实现] 用户自助申请临时角色 + 管理员审批（通过/驳回）。


四、知识库与文档治理
-----------------------------------------------------
20. [已实现] 文档库：53 份模拟文档，PDF / Word / Excel / PPT / Markdown，按部门组织，密级 1–4。
21. [已实现] 结构化解析与切块：按章节/工作表/幻灯片切分，正文约 800 字符、表格约 1500 字符，
            每块带 [标题 | 部门 | 章节] 前缀。
22. [已实现] 向量化：本地 Qwen3-Embedding-0.6B（1024 维），结果按内容哈希磁盘缓存。
23. [已实现] 版本治理：archived / deleted 状态的文档永远不会被检索或引用。
24. [已实现] 目录动态同步（后端每 30 秒自动扫描 data/，LIBRARY_SYNC_INTERVAL 可调，0 关闭）：
      - 新增文件：按 manifest.json 的权限入库；若是同名文件的新版本（如 “X -v 2.0.docx”），
        继承上一版本的权限；两者都没有则不入库并报告（缺少权限信息，fail closed）。
      - 新版本：旧版本自动归档并移出索引，回答只来自最新版本。
      - 内容修改：按内容哈希检测，只重新解析、重新向量化并替换该文件的 chunk。
      - 文件删除：标记 deleted 并移出索引；若删除的是最新版本，自动恢复上一版本为 active。
      - 删除的版本重新放回：自动取代已恢复的旧版本。
      - 保护：目录为空/未挂载时中止，不会清空索引；写入不足 2 秒的文件先跳过。
25. [已实现] 手动同步：命令行 python sync_library.py；接口 POST /api/admin/library/sync（仅 platform_admin）。
26. [已实现] 批量重新入库：seed_data.py / seed_vectorstore.py。
27. [未实现] PostgreSQL/Oracle CDC（Debezium + Kafka）、蓝绿索引切换、多版本并存治理、术语映射层。


五、检索与回答流水线
-----------------------------------------------------
28. [已实现] 检索 RETRIEVE_K=10 候选 → 相关性门槛 → 交给 LLM SERVE_K=5 块，
            并补前两名命中的相邻块；同文档块按原文顺序排列。
29. [已实现] allow / deny 措辞判定（相似度启发式，只影响说法，不影响权限）：
            可见范围内有答案 → allow；真正的答案是受限的 → deny；整库都没有 → allow 并回答“未检索到相关内容”。
30. [已实现] 回答末尾标注来源。
31. [部分]   拒绝措辞是启发式：少数受限问题会得到“资料不足”而不是明确的“权限不足”
            （评测约 11/38 道受限题），此时没有任何受限事实暴露。
32. [已实现] 检索评测（backend/eval/，152 题，中英文）：上下文含答案比例 0.98，
            答案类题目允许判定 1.00，受限事实暴露 0。


六、审计
-----------------------------------------------------
33. [已实现] 每次查询（allow / deny）、登录、授权、撤销都追加写入审计日志。
34. [已实现] 哈希链防篡改：每行链接上一行哈希，可端到端校验，定位首个被破坏的记录。
35. [已实现] 记录有效角色、过滤条件、命中文档、判定、延迟；被拒记录标出用户想看的受限文档
            （blocked_doc_ids，仅审计可见，不会出现在任何用户响应里）。
36. [已实现] 审计查询：按关键词、用户、判定、文档、时间窗口筛选；CSV / JSON 导出。


七、管理后台（/admin，仅 platform_admin）
-----------------------------------------------------
37. [已实现] /admin/dashboard：查询量趋势、拒绝率、越权告警。
38. [已实现] /admin/roles：用户与角色、直接授予/撤销、项目成员、临时角色申请审批。
39. [已实现] /admin/audit：审计日志列表与详情、筛选、导出、哈希链完整性校验。
40. [部分]   /admin/datasources：静态说明页，没有真实的同步任务或数据
            （目录同步通过后台线程、命令行或接口完成）。


八、MCP 审计智能体接口（/mcp，只读）
-----------------------------------------------------
41. [已实现] streamable HTTP，认证 Authorization: Bearer <JWT>，身份为 platform_admin 或 auditor
            （mint_audit_token.py 可生成长期令牌）。
42. [已实现] 工具：get_current_time、find_documents、search_audit_logs、audit_summary、
            list_users、get_user_roles、list_audit_logs、get_audit_log_detail、
            verify_audit_chain、list_role_requests、get_dashboard_stats。
43. [已实现] 与 WorkBuddy 智能体配合：管理员用自然语言问“过去一周谁越权查询过薪酬文档”，
            智能体自行组合工具查证。故意不提供授权/撤销/审批类写工具。


九、可插拔后端（环境变量切换）
-----------------------------------------------------
44. Embedding：local（默认）/ hunyuan / mock
45. LLM：anthropic（Claude）/ openai_compat（Ollama、TokenHub、vLLM）/ hunyuan / deepseek / mock
46. 向量库：qdrant（默认）/ tencent_vectordb
47. OCR：tesseract（默认）/ tencent
    说明：腾讯云适配器（hunyuan、tencent_vectordb、tencent OCR）代码已写好，
    但从未连接真实账号验证；当前实际运行的是 本地 Qwen3 embedding + Claude 或 Ollama + Qdrant + Tesseract。


十、部署与运维
-----------------------------------------------------
48. [已实现] Docker Compose 一键启动：start.sh（--reset 清空重来）/ stop.sh（--purge 删数据卷）。
49. [已实现] 启动时自动迁移数据库、空库时写入种子数据、回填审计哈希链。
50. [已实现] 后端启动时后台预热 embedding 模型，首次查询无冷启动延迟。
51. [已实现] 前后端热更新（代码目录挂载，后端 --reload，前端开发服务器）。


十一、已知限制
-----------------------------------------------------
- 语音查询未实现。
- 数据源管理页为静态说明页。
- 目录同步不改写 manifest.json（文档库只读挂载）；重新执行 seed 脚本会回到 manifest 状态，
  再运行一次同步即可补回新增/更新。
- 目录同步对 Tencent 向量库的 delete_doc 未经真实账号验证；Qdrant 已实测。
- 目录同步目前没有自动化测试（仅手动验证新增、更新、删除、版本归档与恢复）。
- 腾讯向量库适配器的 status（归档）过滤只在 Python 层生效，大库下结果可能少于 top_k。
- 相似度阈值与 embedding 模型、切块方式绑定，更换后必须重新标定（backend/eval/NOTES.md）。
- 模拟 SSO 无密码，仅用于演示；部署前必须修改 JWT_SECRET。
- LLM 回答正文里标注的引用目前仍是内部 doc_id（页面下方的来源标签已显示真实文件名）。
